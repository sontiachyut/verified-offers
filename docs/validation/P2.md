# P2 validation — PostgreSQL transactions

Recorded: 2026-09-08. Synthetic local fixtures only.

## Reproduce

```sh
./mvnw --batch-mode --no-transfer-progress verify
node scripts/demo.mjs
```

Requires Java 21, Docker and Node.js 22+. Failsafe integration tests run by default during verify; unavailable Docker fails the gate rather than skipping it. Unit tests alone are insufficient. Surefire and Failsafe reports are generated under target/ and not committed.

## Environment and result

- Local macOS arm64; Java 21.0.8, Maven wrapper 3.9.16, Spring Boot 4.1.1, Testcontainers 2.0.5.
- PostgreSQL 17.11 Alpine, pinned manifest digest `sha256:18cfe3ef5e6815560c98237d6216d1e5119702fb0f3894c8785dd58b8bbe5d73`.
- 22 unit/HTTP + 8 PostgreSQL/process tests = 30 passing; no failures, errors or skips.
- The original in-memory HTTP walkthrough also passes.
- CI uses Ubuntu/Java 21 and runs full verification plus the Node 22 HTTP demo. Its run on the relevant commit is the source of CI status.

## What was exercised

- Identical replay writes exactly one version/event; changed same-version and lower-version requests conflict without side effects.
- Immutable history retains earlier versions; ordinary UPDATE/DELETE is rejected by a database trigger.
- Injected outbox failure rolls back head, history and new identity creation.
- 100 concurrent identical first writes through two independent pools produce one version/event.
- 100 competing source versions converge on the largest accepted version; event count matches committed history.
- PostgreSQL microsecond precision, freshness, deletion and tenant-key checks.
- A packaged API is forcibly killed after acknowledging a committed write. A new JVM reads the same offer and replays without another event.

## Boundaries

These are correctness/recovery experiments, not load benchmarks. There is no published throughput/P99 measurement, hardware sizing claim or high-availability result. Killing an application after commit does not test database disk loss, database crash recovery or restore. Testcontainers databases are isolated and disposable; Compose data is not touched. Outbox delivery and consumer replay are P3 work.

The database image scan has unresolved findings and covers only the local arm64 variant; see [security evidence](IMAGE-SECURITY.md). Passing functional tests does not approve deployment.

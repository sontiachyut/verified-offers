# P3c1 validation: lexical retrieval and authoritative search

Date: 2026-09-15. This slice does not complete P3's online rebuild gate.

Result: **70 tests passed** (36 unit/HTTP/helper + 34 integration), zero failures,
errors or skipped tests. Final full gate uses OpenSearch 3.8.0. The four-assertion
HTTP reference demo also passes. See [image scan](OPENSEARCH-IMAGE-SECURITY.md) for
the unresolved security gate; tests are not a security certification.

## Commands

```sh
./mvnw --batch-mode --no-transfer-progress verify
node scripts/demo.mjs
```

The acceptance suite uses actual PostgreSQL, Kafka and OpenSearch containers,
with the same pinned manifests as Compose. Docker is required; no dependency
tests are silently skipped. Synthetic fixtures only, local Apple Silicon / Java
21. CI separately verifies the pushed revision on Ubuntu / Java 21.

## New evidence

- External source versions: newer snapshots win, equal/older events are no-ops,
  same-version changed content cannot overwrite, and retained tombstones reject
  resurrection. Tested through real OpenSearch, not a mocked index.
- Explicit write aliases: a missing alias produces an error instead of creating
  an unconfigured index. The strict JSON mapping is shared with the walkthrough.
- Tenant-filtered lexical candidates. One bounded PostgreSQL batch reads current
  facts, and search checks the same returned snapshots. Price/stock/delete lag,
  missing facts, changed versions and exact freshness expiry cannot return
  VERIFIED results. Provenance reports source/index versions and as-of time.
- Real Kafka projection/offset-commit gap: inject a crash after acknowledged
  indexing, verify offset unchanged, recreate consumer and safely replay the
  original record. A later injected transient projection failure rewinds the
  position, preserves the committed offset and recovers to the newer version.
- Real Kafka poison handling: durable quarantine precedes offset progress, and
  the next valid snapshot is processed. Repeating a poison record stores one
  quarantine row. Envelope tests reject unsupported schemas, identity/type/version
  mismatches, missing primitive fields, coercions, overflow and oversized input.
- Packaged API flow: ingest → PostgreSQL outbox → Kafka → OpenSearch → verified
  HTTP search. Check tenant separation and invalid limits/cursors. Pause the
  actual index container: search returns generic HTTP 503; resume and gracefully
  shut down the process without forced termination.
- Adapter rejects non-loopback URLs, unsafe names, partial/malformed/oversized
  responses and unrelated 409 errors. HTTP response cap is 1 MiB; operation
  deadline is 5 seconds, connect deadline 2 seconds.

## Boundaries

These tests demonstrate local correctness and selected crash/outage behavior,
not throughput, latency targets, distributed failover, audited quarantine replay,
online index rebuilds, query relevance quality or production readiness.
Kafka fetch budgets are not a hard hostile-record memory cap: the broker can
return an oversized first record batch. Broker-side record/admission limits and
authenticated producer access remain deployment gates.

The initial integration run exposed shared synthetic identity interference in
the packaged pipeline fixture; a unique tenant isolates its historical topic
records. No test was removed or skipped to resolve it.

Remaining P3 work: rebuild PostgreSQL heads (including tombstones) into a new
index, bounded Kafka catch-up, completeness/version checks, atomic alias switch
and failure/rollback tests. Stable PIT pagination and audited index-quarantine
replay/retention are also open. See ADR 0004 and STATUS.md.

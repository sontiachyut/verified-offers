# Optional cross-project integration (future)

Status: design only. Both applications remain independently runnable.

Verified Offers produces an offer reference (tenant, merchant, offer, source version, as-of timestamp); inventory-fulfillment owns (tenant, SKU) and stock. An explicit merchant-offer-to-SKU mapping is needed. Never assume offerId equals SKU implicitly.

A future UI discovers an offer, submits an idempotent reservation to inventory, and handles insufficient stock even after successful offer verification. Search availability is never allocation authority.

If stock events update merchant feed availability, versions must be generated by a single adapter with a durable source-sequence mapping, so publisher retries do not create conflicting feed versions. No shared database and no cross-service distributed transaction.

Price acceptance and price changes between discovery and checkout require a quote contract. P1 inventory has no price/payment amount, so integration must not pretend price locking already exists. Settle quote validity, expiry, currency and consent before adding that flow.

Write consumer/provider contract tests and event compatibility tests before connecting runtimes. No shared runtime dependency is required to demonstrate either project.
